## 2. Executive summary

Yêu cầu hiện có: Windows single-user, loopback, dữ liệu local, trusted selection hoặc streamed upload, COPY/LINK, Job bền vững tối thiểu, không Supabase. Đề xuất MVP: backend phục vụ UI và API **cùng origin** `http://127.0.0.1:<port>`; launcher khởi tạo phiên ngắn hạn, Host/Origin/CSRF và Fetch Metadata được kiểm tra; native Windows picker do helper local mở, backend cấp selection handle opaque. Worker có Windows Job Object để hủy process tree. Đây là hợp đồng mục tiêu, chưa đo hoặc kiểm thử trên Windows. Không có lease/heartbeat phân tán, multitrack, video stretch, Vocal Separation hay backup đầy đủ trong MVP.

## 3. Threat model và trust boundaries

Browser UI → loopback API là boundary không tin cậy: website ác ý có thể gửi form, fetch hoặc nhúng media; CORS chỉ điều khiển khả năng đọc một số response, không ngăn mọi request hay CSRF. DNS rebinding và Host giả có thể đổi ngữ cảnh origin. Selection handle là quyền giới hạn, không phải path do browser cấp. API → worker là kênh nội bộ có typed snapshot, không tin nội dung model. Repository/SQLite lưu metadata; filesystem chỉ truy cập theo registered asset/selection. Gemini/Edge nhận text theo từng tác vụ.

Đe dọa: cross-origin/CSRF; Host/DNS rebinding; mutation không có session; traversal, thiết bị Windows, junction/symlink và đổi file sau chọn; đoán ID của project khác; port bị chiếm; duplicate requests, concurrent edit và cancel race. Mục tiêu bảo vệ website khác và thao tác nhầm. Không hứa chống mọi process độc hại hay browser extension chạy dưới cùng Windows account, XSS trong chính UI, hoặc quản trị viên máy. CSP, dependencies và output encoding giảm rủi ro XSS nhưng không thay thế kiểm tra API.

## 4. MVP security decisions

1. **Bind** chỉ IPv4 `127.0.0.1` cụ thể, không `0.0.0.0`, không `localhost` hay IPv6 implicit. Launcher bind port động trước khi mở browser; port đã chiếm không kết nối vào service lạ, fail rõ hoặc chọn port mới. Không trust proxy headers từ client. Kiểm peer loopback và đúng `Host: 127.0.0.1:<actual-port>` trên mọi route, kể cả static và health; reject hostname, sai port, duplicate/malformed Host. Không dùng wildcard hoặc suffix matching.
2. **Bootstrap:** launcher sinh secret ngẫu nhiên ≥256 bit mỗi lần chạy, mở đúng origin với secret một lần trong URL fragment (fragment không gửi trong HTTP); static bootstrap page cùng origin đọc fragment, xóa ngay bằng `history.replaceState`, POST JSON qua same-origin tới `/api/v1/session/bootstrap` với secret trong header. Server so sánh constant-time, một lần, TTL ngắn (đề xuất 60 giây), rate limit; không đặt secret trong query, log, referrer, console, response hoặc persistent storage. Token được đưa cho browser bởi launcher; không có endpoint cấp token vô điều kiện. Browser history/process command line và phần mềm cùng user có thể lộ bootstrap: nằm ngoài giới hạn bảo vệ trước local malicious process. Hết hạn/đã dùng → mở lại qua launcher. Không redirect sang origin khác; CSP `default-src 'self'; object-src 'none'; base-uri 'none'; frame-ancestors 'none'`, `Referrer-Policy: no-referrer`, `Cache-Control: no-store`, `X-Content-Type-Options: nosniff`; không nhúng tài nguyên bên thứ ba.
3. Bootstrap endpoint là ngoại lệ chưa có session/CSRF: yêu cầu exact Host, exact Origin, `Sec-Fetch-Site: same-origin`, JSON và secret một lần; từ chối cross-origin trước khi kiểm secret. Bootstrap cấp cookie session ngẫu nhiên HttpOnly, SameSite=Strict, Path=/, host-only, không Domain; HTTP loopback không đặt `Secure` vì không có HTTPS. Session hết hạn, logout/restart thu hồi, không lưu trong localStorage. Bootstrap trả CSRF token ngẫu nhiên session-bound trong JSON `no-store`; JS giữ trong memory và gửi `X-CSRF-Token` với mỗi mutation, bao gồm picker và job. Sau reload, GET `/session/csrf` cấp token cho session hiện tại chỉ khi exact Host, session và `Sec-Fetch-Site: same-origin`, Origin nếu có phải khớp; response `no-store` và không CORS. Mutation khác bắt buộc exact Origin `http://127.0.0.1:<port>`, CSRF, session, JSON content type; reject Origin thiếu/null/khác, `Sec-Fetch-Site` khác `same-origin` nếu có, không cho form/simple requests. Browser cũ thiếu khả năng bắt buộc được báo unsupported thay vì hạ bảo vệ. CSRF token không vào URL/log.
4. **GET/HEAD nhạy cảm**, kể cả media: session bắt buộc và exact Host; nếu Origin có thì phải khớp; `Sec-Fetch-Site: same-origin` bắt buộc trong browser hỗ trợ, reject `cross-site`, `same-site`, `none` và thiếu khi không có chính sách fallback an toàn đã kiểm thử. Không bắt buộc Origin cho media vì browser có thể không gửi; không dùng GET thay đổi state. Static bootstrap là ngoại lệ không chứa dữ liệu/secret. Không hỗ trợ truy cập trực tiếp media bằng mở tab `none`; phát qua UI cùng origin. Không dựa riêng vào SameSite vì site cùng host khác port có thể là same-site.
5. **CORS:** production không gửi `Access-Control-Allow-Origin` hay credentials cho origin khác; reject preflight cross-origin. Development phải giữ cùng các kiểm tra Host, Origin và CSRF như production, bất kể công cụ build hay cách phục vụ UI; nếu có proxy, proxy chỉ được tin cậy theo cấu hình và kênh được xác thực rõ. Không wildcard CORS, không tắt guard. Exact public origin/port áp dụng trong từng phiên. Không có external API client trong MVP.
6. Limits có cấu hình: body JSON nhỏ có giới hạn, request ID/server-generated, max length/array, cap số selection và concurrent jobs, streaming upload có quota/disk preflight; 413 khi vượt. Rate limit theo session và loopback, đặc biệt bootstrap/picker; 429 + Retry-After. Giá trị cụ thể cần benchmark, không tự nhận là giới hạn provider. Redact cookie, authorization, CSRF, selection handle, URL fragment/query, key, text dialogue, private paths và trace; response error chỉ code/message/details an toàn. Không tin `Origin` hay Fetch Metadata như bằng chứng về local process.

## 5. Windows picker evaluation

| Phương án | COPY / LINK / roots | Bảo mật, browser và Windows | Chi phí / khả năng kiểm thử |
|---|---|---|---|
| A. Native picker bởi trusted launcher/helper | COPY + LINK, file và folder | Có thể mở từ web request đã xác thực, dialog Windows do helper sở hữu; chỉ handle được cấp sau tương tác; Unicode/long path cần test thực | Cần thread COM/STA, lifetime/cancel và đóng gói; test Windows interaction thật |
| B. Browser upload streaming | COPY; browser không cấp authority cho LINK hay folder backend | Không cung cấp path gốc đáng tin; streaming/quota/cancel; Unicode tên hiển thị riêng | Ít bridge; không đáp ứng LINK/root; vẫn cần kiểm security và disk |
| C. Desktop shell/bridge | Đủ COPY/LINK/root | Native bridge có thể giới hạn capability; bổ sung bề mặt IPC/shell | Đóng gói và dependency lớn hơn; test tương thích browser/shell |

**Khuyến nghị mới:** A, helper do launcher quản lý, UI vẫn dùng browser. B có thể làm fallback COPY nếu được duyệt, không giả vờ hỗ trợ LINK/root; C hoãn nếu helper không đáp ứng. Picker chạy STA có message loop riêng và owner window có thể hiện dialog; serialize mỗi session, có timeout và lệnh cancel đóng dialog trên đúng thread, helper crash → error, không cấp handle. Không giả định headless/service session có UI: báo `picker_unavailable`. Không nhúng full path vào API. **PENDING OWNER DECISION:** native dialog và hỗ trợ fallback upload ảnh hưởng trải nghiệm; giới hạn chọn network paths cần xác nhận.

## 6. Trusted file selection contract

`POST /api/v1/selections` body `{ "purpose":"source|relink|data_root|output_root", "project_id":"uuid-or-null" }`; yêu cầu session/Host/Origin/CSRF. Helper chỉ trả kết quả sau user chọn; API trả opaque `selection_id` từ CSPRNG ≥256 bit, purpose, display name đã sanitize và `expires_at`, không trả path. Dialog dài có thể trả `202 {selection_request_id}` rồi poll `GET /selections/requests/{id}`, cancel bằng POST cùng guard. Mỗi selection là record server-side: session, operation, project khi áp dụng, canonical path và file identity/volume/metadata lưu riêng không log, issued/expiry, state. Đề xuất TTL 5 phút; restart/session end thu hồi selection chưa consume; selection không cho sửa path. Consume một lần trong transaction cùng tạo Job hoặc cập nhật settings; cùng idempotency key/payload retry trả kết quả cũ, key khác replay → 409. Expired → 410 `selection_expired`; sai session/purpose/project → 403 hoặc 404 theo policy; đã dùng → 409 `selection_consumed`. TTL là candidate. Import Job snapshot đã commit vẫn được reconcile sau restart theo durable lifecycle bên dưới.

**Durable Selection → Import Job:** lifecycle là `ISSUED → CONSUMED → AUTHORIZED_JOB_INPUT → VERIFIED|FAILED`. Tạo Import Job consume selection và ghi durable Job input snapshot trong cùng transaction SQLite; snapshot giữ tham chiếu nguồn đã được user cho phép, selection purpose/project, source identity (volume/file identity), baseline metadata/hash theo policy, mode COPY/LINK và input fingerprint, trong vùng lưu trữ riêng không trả absolute path qua API hoặc ghi log. Sau commit, token hết hạn/revoke không thu hồi quyền xử lý có phạm vi của Job hợp lệ. Retry cùng idempotency key trả Job đã tạo và không consume lại selection; retry khác không được tái sử dụng token. Sau restart, reconciliation chỉ tiếp tục từ snapshot đã commit và trước mỗi lần mở nguồn phải kiểm tra lại identity/integrity; nguồn mất, đổi hoặc không thể xác minh thì `FAILED`/review, không tự chọn file thay thế. Quyền snapshot chỉ phục vụ Job đã tạo và không được dùng làm capability dùng chung cho API khác.

Picker trả đường dẫn tuyệt đối; relative, traversal, NUL, device namespace/CON/PRN/AUX/NUL/COMn/LPTn, alternate streams và tên không an toàn bị từ chối. Unicode được giữ chính xác, không tự biến đổi tên; dùng Windows wide APIs, kiểm long path và báo giới hạn actionable khi tool không hỗ trợ. Không đặt DB WAL trên UNC/network filesystem; MVP đề xuất từ chối UNC/network cho roots và source cho tới khi policy được duyệt. Chọn source LINK ngoài managed root là ngoại lệ duy nhất theo selection đã duyệt, không cấp quyền duyệt cây thư mục.

**Trusted helper IPC:** chỉ picker helper do launcher khởi tạo/quản lý mới được phép trả kết quả selection. Backend và helper dùng IPC cục bộ được xác thực, giới hạn ACL cho Windows user hiện tại; request chứa nonce ngẫu nhiên dùng một lần, request ID, purpose/project, deadline và trạng thái hủy. Backend ghép đúng response với request còn hiệu lực, xác minh nonce, schema, helper identity, deadline và kết quả chọn trước khi tạo selection record. HTTP không nhận path và không thể tự tạo trusted selection bằng gửi path hoặc giả response IPC. Timeout, helper crash, response trùng/sai nonce hoặc cancel kết thúc request bằng lỗi an toàn, không cấp selection; helper đóng dialog và dọn IPC handle. Hạn chế bảo vệ trước process độc hại cùng Windows user phải được nêu rõ.

Kiểm từng component với reparse point/junction; đối với managed root từ chối escape, và fail closed nếu không thể chứng minh. Resolve/open bằng handle và kiểm final identity/volume, loại file, đường dẫn cuối và root sau open; không coi canonical string prefix là đủ. Với source LINK đã chọn rõ, từ chối reparse không giải quyết an toàn; không mặc định đi theo junction. Mỗi lần consume/reopen so file ID/volume, size/mtime và hash theo policy; metadata một mình không chứng minh content. COPY đọc từ handle đã xác thực, hash trong khi copy, so identity/metadata trước và sau, probe bản copy, kiểm disk và publish mới; nếu thay đổi/không đảm bảo consistency thì `source_changed`, giữ source, retry lựa chọn. LINK trước xử lý/playback mở và kiểm identity/hash theo policy; nếu đổi/mất, ngừng dùng, yêu cầu relink/review, không âm thầm thay source. So sánh path trước open không loại được mọi TOCTOU; nếu không thể buộc consumer FFmpeg đọc cùng object đã kiểm, staging bản cố định hoặc fail closed và review, không cam kết chống local attacker.

## 7. COPY/LINK và ownership

COPY: copy vào scratch thuộc data_root, verify size/hash và FFprobe, atomic publish managed asset, commit DB; original không xóa. LINK: lưu đường dẫn đã user chọn trong DB local, identity/hash, không di chuyển/xóa/ghi đè; thiếu → MISSING, thay đổi → CHANGED, không READY; relink bằng selection purpose riêng và verify, mismatch yêu cầu user review/new asset identity, giữ run cũ. `data_root` và `output_root` phải được chọn qua picker, capability được consume; chỉ lưu approved roots; các thay đổi root không tự di chuyển/xóa dữ liệu. Không dùng arbitrary JSON path, filename template phải sanitize. Output ghi tên mới và cross-volume copy+verify+rename như ARCH-00A, không overwrite verified output.

**DataRoot lifecycle:** lần thiết lập ban đầu được phép chọn `data_root` trước khi khởi tạo database và Project. Khi database/artifact đã hoạt động hoặc đã có Project, PATCH thay `data_root` phải bị từ chối rõ ràng (`409 data_root_migration_required`) cho tới khi có migration được thiết kế, kiểm chứng và owner duyệt. Không âm thầm khởi tạo database rỗng ở root mới; không tự di chuyển, xóa hay bỏ orphan dữ liệu cũ. `output_root` là cấu hình độc lập và có thể đổi qua selection hợp lệ; thay đổi này không di chuyển artifact đã công bố.

## 8. Media streaming HTTP contract

`GET|HEAD /api/v1/projects/{project_id}/media/{asset_id}/stream`: guard §4, kiểm asset FK đúng project, READY và permission, resolve registered asset, mở handle hợp lệ/kiểm identity; không chấp nhận `?path=`. Source LINK missing/changed → 404 `asset_unavailable` hoặc 409 `asset_changed`, không stream bản khác; temp/unverified → 404. Chỉ whitelist MIME xác định từ probe/decoder và loại được hỗ trợ; không dùng extension/browser input làm authority, `nosniff`, không inline HTML. TTS playback áp dụng cùng quy tắc, kiểm revision/fingerprint.

- Không Range: 200, `Content-Type`, `Content-Length`, `Accept-Ranges: bytes`, strong ETag từ identity + verified content hash cho file immutable. `HEAD` cùng headers như GET tương ứng nhưng không body; Range trên HEAD bỏ qua, trả metadata 200. `Cache-Control: private, no-store` ưu tiên riêng tư; ETag vẫn hỗ trợ conditional validation trong phiên nếu client gửi `If-None-Match`, 304 khi tương ứng. Không cache public.
- `Range: bytes=0-1023` với size ≥1024 → 206, `Content-Range: bytes 0-1023/<size>`, `Content-Length: 1024`, `Accept-Ranges: bytes`; hỗ trợ single open-ended/suffix hợp lệ, clamp end. `If-Range` đúng strong ETag → 206; mismatch → 200 toàn bộ. Range hợp cú pháp nhưng không thỏa → 416, `Content-Range: bytes */<size>`; malformed hoặc multi-range: 400 `invalid_range` theo contract MVP, không giả multipart. Không nạp cả file vào memory.
- Ví dụ: `GET …/stream` → `200 Content-Length: 10000`; `Range: bytes=9000-` → `206 Content-Range: bytes 9000-9999/10000`; `bytes=10000-` → `416 Content-Range: bytes */10000`. Handle đóng khi client disconnect; nếu file đổi trong lúc đọc, kết thúc stream lỗi, đánh CHANGED, không phục vụ các request sau cho tới kiểm tra lại. HEAD/GET không thay đổi state nghiệp vụ, ghi chẩn đoán integrity an toàn là ngoại lệ nội bộ.
- Chặn cross-project asset, `../`, `?path=`, origin lạ, reparse escape, symlink replacement và artifact STAGING; không rò path trong lỗi. Browser `<video>` cùng origin và session cookie gửi Range theo §4; browser không có Fetch Metadata cần kiểm thử trước khi hỗ trợ, fail closed mặc định.

**Development session security (độc lập công cụ build):** browser chỉ dùng một public origin đã khai báo cho UI, bootstrap, API và media. Thành phần nhận request từ browser kiểm exact `Host` với listener/origin được cấu hình và exact `Origin` với public origin; không suy ra origin từ giá trị do client tự gửi. Nếu có reverse/dev proxy, proxy là trust boundary riêng: chỉ listener/kênh proxy đã xác thực được chấp nhận, proxy phải loại bỏ forwarded headers đầu vào không tin cậy rồi ghi giá trị chuẩn; backend chỉ tin các giá trị từ proxy xác thực. Không được nới allowlist Host/Origin hoặc tắt CSRF để development chạy được, không wildcard CORS. Bootstrap/session/cookie và media Range phải hoạt động cùng public origin. Cookie không được phân phạm vi theo port; các port `localhost` cùng host có thể nhận cookie cùng host, vì vậy mọi listener vẫn phải kiểm Host/Origin/Fetch Metadata và không dựa vào port như ranh giới cookie. Các kiểm tra này không bảo vệ khỏi process độc hại chạy dưới cùng Windows user biết port/session.

## 9. API endpoint specifications

Prefix `/api/v1`. Quy ước: mọi endpoint trừ bootstrap/static yêu cầu session, exact Host và guard GET/HEAD hoặc mutation §4; ID project được kiểm membership local. Payload versioned `schema_version`, UUID chuẩn, JSON; fields không khai báo reject, enum/bounds validate. `K` = `Idempotency-Key` random cho creation/side effect có thể retry, lưu scope + canonical request digest; cùng key/cùng payload trả response gốc, khác payload 409, hết retention theo policy được công bố. `CAS` = `expected_lock_version` (hoặc `If-Match` nhất quán), mismatch 409 và draft client được giữ; Job snapshot gồm fingerprint/input generation và activation CAS theo ARCH-00A §9. Mọi Job create trả `202 {job_id,status,kind,project_id,input_fingerprint}` và `Location: /api/v1/jobs/{id}`; no long inference trong request. 401/403/404/422/429/500 áp dụng chung theo §10.

| Nhóm / method path | Request → response; validation, concurrency, side effect |
|---|---|
| `POST /session/bootstrap`, `GET /session/csrf`, `POST /session/logout` | Bootstrap one-time header → session cookie + CSRF theo §4; GET cấp lại CSRF cho session cùng origin → 200 no-store; logout CSRF → 204, revoke. Bootstrap sai/hết hạn 401/429; không log secret. |
| `GET /health` | → `{backend,db,supervisor}` readiness; không tiết lộ path/secret; 200 hoặc 503 `not_ready`. Session guard; không gây side effect. |
| `GET /hardware/capabilities` | → `{cpu,ram,gpu,ffmpeg,states}` configured/tested/fallback; chỉ kết quả thực đã probe, chưa test hiển thị NOT_TESTED; 200. |

## 10. Error envelope và status

Envelope `{error:{code,message,retryable,details},request_id}`; message tiếng Việt, details whitelist ID/revision hiện tại, không trace/path/secret/text; đồng nhất response ngoại trừ 416/HEAD có header bắt buộc. 400 malformed JSON/range, 422 schema/domain input, 401 thiếu/hết phiên, 403 origin/CSRF/purpose denied, 404 không tồn tại hoặc không được tiết lộ, 409 CAS/idempotency/replay/changed/stale, 410 expired selection, 413 quota body, 416 range unsatisfiable, 429 limit + Retry-After, 500 internal sanitized, 503 service unavailable. Không biến provider failure thành 200 success: Job status FAILED/REVIEW_REQUIRED có `error.code`, retryability; 202 chỉ nghĩa đã nhận Job. Permission khác project dùng 404 để không lộ sự tồn tại.

## 11. Job lifecycle và Windows cancellation

Theo ARCH-00A §11: QUEUED→RUNNING→READY/FAILED/INTERRUPTED hoặc CANCEL_REQUESTED→CANCELLED; queued cancel trực tiếp, retry FAILED/INTERRUPTED khi hợp lệ. Một local supervisor claim `BEGIN IMMEDIATE`, insert JobAttempt cùng transaction; không giữ transaction khi FFmpeg/network/inference. Poll trả `phase`, `completed_units/total_units` khi biết, elapsed và `progress=null` nếu không đo được; attempt state và activation ACTIVE/STALE độc lập với Job/Artifact READY. Duplicate K trả cùng job; cancellation idempotent. Cancel commit trước completion → không activate, verified historical artifacts có thể giữ; completion commit trước cancel → READY, báo already completed. TTS partial giữ Unit READY riêng.

Khuyến nghị Windows Job Object riêng cho mỗi Attempt: supervisor tạo process suspended, gán vào Job Object trước resume để tránh child thoát trước assignment; disable breakaway, không chia sẻ/inherit handle không cần thiết, giữ handle; yêu cầu cooperative cancel qua IPC, grace period có giới hạn rồi terminate Job Object, chờ process exit/reap và đóng handles. Job Object mặc định bao gồm child tạo bằng CreateProcess, có ngoại lệ và policy breakaway; `KILL_ON_JOB_CLOSE` có thể hỗ trợ khi supervisor chết nhưng chỉ nếu last handle đóng, cần kiểm thử nested job/hosting và lifetime. Process-group console signal chỉ là cooperative, không bảo đảm kill toàn bộ tree; không dùng `taskkill` theo PID đơn lẻ làm bảo đảm. Nếu assign thất bại, không chạy job không được giám sát; trả lỗi actionable. Process creation của tool được kiểm soát; child tạo ngoài boundary không được coi là đã bao phủ.

Nếu không xác nhận dừng sau timeout, giữ CANCEL_REQUESTED, báo `cancel_failed`, không READY hoặc cleanup dữ liệu đang dùng; tiếp tục giám sát. Restart: PID có thể tái sử dụng; không kill PID cũ chỉ dựa vào số. Reconcile attempts RUNNING/CANCEL_REQUESTED thành INTERRUPTED sau xác minh ownership/lifetime, validate manifest/files và DB theo ARCH-00A D1–D7, giữ verified output, retry eligible rõ ràng. Chưa xác nhận tính khả thi của Job Object/Windows trên host này: NOT RUN.

## 12. Settings, secrets và privacy

App settings lưu approved data/output roots, default import_mode, resource profile, provider config không secret và capabilities đo được; Project settings override theo policy; mỗi Run chụp immutable effective config/version. API trả root selection trạng thái/tên hiển thị, không full path; diagnostics trả dung lượng/loại volume và trạng thái đã sanitize. `GET /settings` trả `gemini_key_configured: true|false`, không trả key. `PUT /settings/credentials/gemini` nhận secret qua body JSON với session/Origin/CSRF, no-store, không echo; DELETE xóa credential explicit. Ưu tiên Windows Credential Manager/DPAPI bảo vệ theo user, đánh giá packaging; `.env` ignored là fallback local cấu hình qua operator, không export; không hứa bảo vệ chống process cùng user. Không secret trong URL, Job snapshot, logs hay project export.

UI thông báo media/database lưu local; khi dịch transcript được gửi Gemini, khi synth text được gửi Edge-TTS. Không gọi sản phẩm hoàn toàn offline. Voice/rate là snapshot, FFmpeg capability chỉ `configured/tested/fallback`, diagnostics không phát lộ private path. Hardware và provider limits chưa benchmark.

## 14. Trade-offs

Native helper đáp ứng LINK/root nhưng có STA, UI lifetime và phụ thuộc Windows; browser upload đơn giản hơn nhưng chỉ COPY. Cookie HttpOnly cho media seek, nhưng cần Fetch Metadata để xử lý cross-origin embedding khi Origin vắng mặt; hỗ trợ browser cũ có thể bị giới hạn. Bind port động tránh kết nối nhầm service nhưng launcher phải truyền đúng port. Kiểm hash và giữ handle tốn I/O; fail closed khi FFmpeg chỉ nhận path có thể yêu cầu staging. Windows Job Object giúp quản lý tree nhưng nested job/assignment và handle lifetime cần thực nghiệm; chưa cam kết hỗ trợ mọi subprocess.
